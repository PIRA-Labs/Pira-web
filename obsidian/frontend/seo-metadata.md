# SEO & Metadata

## Site config

`src/lib/site.ts` (`siteConfig`) is the **single source of truth** for SEO —
name, description, origin URL, OG image, Twitter handle, theme colour. The
metadata generator, `robots.ts`, `sitemap.ts`, and the JSON-LD helper all read
from it. **Update the placeholder values per project.** `#todo`

`siteConfig.url` comes from `NEXT_PUBLIC_SITE_URL` (see [[environment-variables]]),
falling back to `http://localhost:3000`.

## Metadata generator

`src/utils/seo/generate-page-metadata.ts` exports two builders:

```ts
import {
  generateMetadata,
  generateViewport,
} from "@/utils/seo/generate-page-metadata";

export const metadata = generateMetadata({ title: "…", description: "…" });
export const viewport = generateViewport();
```

- `generateMetadata(props?)` → a Next.js `Metadata` object: title/description,
  OpenGraph, Twitter cards, canonical, icons, robots. `metadataBase` is **always
  set** from `siteConfig.url`, so relative URLs (OG image, canonical) resolve to
  absolute — required by social scrapers.
- `generateViewport()` → the `Viewport` export. `themeColor` lives here, **not**
  on the metadata object (Next deprecated it there).

Accepted `generateMetadata` options: `title`, `description`, `url`, `ogImage`,
`twitterHandle`, `author`, `siteName`. (`keywords` and the non-standard `other`
tags were dropped — no SEO value.)

## robots.txt & sitemap.xml

Generated by the Next file conventions:
- `src/app/robots.ts` → `/robots.txt` — allows all crawlers, points at the sitemap.
- `src/app/sitemap.ts` → `/sitemap.xml` — lists public routes (home only so far;
  add an entry per route as the site grows).

## Structured data (JSON-LD)

`src/utils/seo/structured-data.ts` → `getSiteStructuredData()` builds an
`Organization` + `WebSite` JSON-LD graph. The root layout renders it once in a
`<script type="application/ld+json">`.

## Bot detection

> [!note] The WebGL scene uses the client-side check (2026-09-14, ADR-0042)
> `src/utils/bot-user-agent.ts` → `isBotUserAgent()` holds the shared pattern.
> `PreloadedGrassField` tests `navigator.userAgent` and serves crawlers and audit
> tools `public/assets/grass-hero/poster.webp`, so the `three` chunk is never
> requested. Doing it client-side keeps `/` statically prerendered; `isBot()`
> below would not.

`src/utils/is-bot.ts` exports `isBot()` — a **server-only** async helper that
reads the `user-agent` header and returns `true` for Lighthouse, Googlebot,
PageSpeed, HeadlessChrome, GTmetrix, Pingdom, Bingbot, Yandexbot.

> [!caution]
> Calling `isBot()` (or any `headers()` reader) in a route **opts it out of
> static prerendering** — a TTFB cost for every visitor. Serving crawler-specific
> behaviour also borders on cloaking. Prefer the [[animation-system|reduced-motion]]
> path (`<ReducedMotion>`): animations only touch opacity/transform, so content
> is always in the DOM and crawlers see it regardless. Use `isBot()` sparingly.

## Static assets

The `public/` **root** holds meta/PWA/SEO assets — favicons (multiple sizes),
Android/Apple icons, `manifest.json`, `browserconfig.xml`, `open-graph.png`.
Site **content** assets (images, videos) go under `public/assets/<section>/` —
see [[folder-structure]].

### Brand assets (generated 2026-09-14)

Every icon and the share image were generated from the **long.play** wordmark
with a one-off Pillow script. The script isn't committed. To regenerate, repeat
the recipe:

| File(s) | What |
|---------|------|
| `favicon.ico` (16/32/48, also `src/app/favicon.ico`), `favicon-16x16.png`, `favicon-32x32.png` | "lp" (the wordmark's initials, `p` at 60 % white as in the logo) in Open Sans 400 on the preloader sky gradient (`#005bdb` → `#ff7a95`), rounded 22 % |
| `apple-icon-180x180.png`, `android-icon-{36…192,512}.png`, `ms-icon-{70,150,310}.png` | Same mark, full-bleed square (the platforms mask it themselves) |
| `open-graph.png` — **1200×630** | The hero as a card: logo top-left, the frame hairlines and brackets, "Tape doesn't last." (Dancing Script 700), the sub-line (Open Sans, 60 %), a formats line, and the trust band (Mulish). |

The fonts are the Google Fonts latin subsets of the site's own families. The
colours are the Tier 1 tokens in `globals.css`.

### Site config

`src/lib/site.ts` holds:
- `name` "long.play".
- `title`, used as the default document title: "long.play — VHS, Hi8, Super 8 & MiniDV digitisation".
- `description`, the hero body copy verbatim (146 chars).
- `ogImageAlt`, `ogImageWidth` / `ogImageHeight`.
- `themeColor` and `backgroundColor` `#005bdb`.
- `twitterHandle` is `undefined`, so no `twitter:site` / `creator` tags are
  emitted until a real handle exists.

`manifest.json` and `browserconfig.xml` carry the same name and colours.

> [!warning] `NEXT_PUBLIC_SITE_URL`
> `og:url`, canonical and `og:image` resolve against it. The local `.env` has
> `https://example.com`. Set the production origin before launch.

## PIRA identity (2026-10-29)

Current metadata reads the PIRA identity from `src/data/pira.ts`. Icons use a
phone-inspired P monogram; the 1200×630 share image carries the PIRA hero copy.
`/about`, `/how-it-works`, `/architecture` and `/download` have canonical metadata
and sitemap entries. The former brand recipes above are historical.
